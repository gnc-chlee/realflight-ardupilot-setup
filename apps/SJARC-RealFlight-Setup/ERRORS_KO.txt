# ArduPlane.exe 시스템 오류: cygiconv-2.dll(또는 cygintl-8.dll)이 없음
검색어: cygiconv cygintl dll 시스템 오류 코드 실행을 진행할 수 없습니다 ArduPlane.exe 다시 설치
상황: Mission Planner Simulation 탭에서 Plane을 누르면 이 창이 뜨고 SITL이 켜지지 않습니다.
원인: Mission Planner 1.3.82는 SITL 보조 파일(cygwin DLL)을 8개만 받는데, 지금 서버의 SITL은 두 개(cygiconv-2.dll, cygintl-8.dll)가 더 필요합니다. 1.3.83부터는 10개를 받습니다. 1.3.83으로 SITL을 한 번도 받은 적이 없는 PC에서 생깁니다(2026-10 이천 현장).
해결:
1. 아래 두 파일을 받아 문서\Mission Planner\sitl 폴더에 넣습니다(ArduPilot 공식 서버).
   https://firmware.ardupilot.org/Tools/MissionPlanner/sitl/PlaneStable/cygiconv-2.dll
   https://firmware.ardupilot.org/Tools/MissionPlanner/sitl/PlaneStable/cygintl-8.dll
   Plane을 누를 때 Latest(Dev)를 골랐다면 주소에서 PlaneStable/을 뺀 같은 이름의 파일을 받습니다.
2. 또는 잘 되는 PC의 같은 폴더에서 두 파일을 USB로 복사해 넣습니다.
3. Simulation 탭에서 Skip Download를 체크하고 Plane을 다시 누릅니다.

# 연결 직후 Mission Planner가 꺼짐 (Mission Planner 1.3.83)
검색어: Mission Planner 꺼짐 종료 사라짐 1.3.83 MP 버전 업데이트 예외 코드 0x00000000 오류 있는 모듈 unknown
상황: SITL에 연결되고 몇 초 뒤 Mission Planner 창이 갑자기 사라집니다. 뒤따라 RealFlight가 '응답 없음'이 되기도 합니다. 도우미 상태 줄에 'MP 1.3.83'이 빨간색으로 보입니다.
원인: Mission Planner 1.3.83의 버그입니다. 연결 직후 보내는 카메라 정보 요청과 다른 연결 작업이 겹치면, 개발자용 중단 명령(Debugger.Break)에 걸려 종료됩니다. 1.3.82는 기록만 남기고 넘어갑니다. Mission Planner 쪽 수정은 아직 정식 배포 전입니다(2026-10 음성 현장, 덤프로 확인).
해결:
1. 제어판 → 프로그램 제거에서 Mission Planner를 제거합니다. 문서\Mission Planner 폴더(설정·SITL·파라미터)는 그대로 남습니다.
2. 1.3.82를 설치합니다: https://firmware.ardupilot.org/Tools/MissionPlanner/MissionPlanner-1.3.82.msi
3. MP를 켤 때 업데이트를 물으면 '아니오'를 누릅니다.
4. 1.3.82로 처음 SITL을 받는 PC는 cygiconv-2.dll 오류가 날 수 있습니다(맨 위 항목).

# SITL 연결 중 RealFlight '응답 없음', MP는 'no heartbeat packets received'
검색어: 응답 없음 멈춤 RealFlight 멈춤 no heartbeat packets received 연결 시도 중 Automatic Reset Delay 리셋 지연 10초
상황: SITL이 붙고 1~2초 뒤 RealFlight가 멈추고, Mission Planner는 '연결 시도 중'에서 'no heartbeat packets received'로 끝납니다.
원인: 기체가 넘어지면 RF가 Automatic Reset Delay(기본 2초) 뒤 자동 리셋을 하는데, SITL이 붙는 도중 이 리셋이 겹치면 RF가 멈춥니다. RF가 멈추면 SITL도 시간이 멈춰 MP에 신호를 보내지 못합니다. 느리거나 메모리가 빠듯한 PC에서 잘 생깁니다(2026-10 음성 현장 2·3번 PC, 10초로 해결).
해결:
1. RF가 멈춘 상태에서 '연결 문제 해결'의 ① 진단을 먼저 만들어 둡니다.
2. 작업 관리자로 RealFlight를 끝냅니다. 세부 정보 탭에 RealFlight.exe가 남아 있으면 모두 끝냅니다(또는 재부팅).
3. RF를 다시 켜고 Settings → Physics → Automatic Reset Delay를 10으로 바꿉니다.
4. 기체를 고르고, 넘어진 채 가만히 있을 때 Simulation 탭에서 SITL을 켭니다.

# SITL 창에 'PANIC: Should not be called on invalid location: Location cannot be (0, 0, 0)' 후 종료
검색어: PANIC invalid location Location cannot be 0 dumpstack dumpcore Failed 개발판 Dev Latest SITL 개발판 Stable
상황: Mission Planner가 SITL에 붙는 순간(New connection on SERIAL0) SITL 검은 창에 PANIC이 나오고 SITL이 꺼집니다. RF에는 'FlightAxis Controller Device has been removed'가 뜹니다. 도우미 상태 줄에 'SITL 개발판'이 보일 수 있습니다.
원인: 예전에 받은 개발판(Latest/Dev) SITL에서 생겼습니다. 홈 위치가 정해지기 전에 MP가 붙으면 SITL 전용 내부 검사가 프로그램을 멈춥니다.
해결:
1. SITL 창을 닫습니다.
2. Simulation 탭에서 Skip Download 체크를 풀고 Plane을 누른 뒤, 버전을 물으면 Stable을 고릅니다.
3. 다 받으면 Skip Download를 다시 체크해 둡니다. 다음부터는 다시 받지 않습니다.
4. 잘 되는 PC의 문서\Mission Planner\sitl 폴더에서 ArduPlane.exe와 cyg로 시작하는 DLL을 복사해 와도 됩니다.

# SITL 검은 창 제목에 '선택'이 붙고 RF·MP가 같이 멈춤
검색어: 선택 검은 창 클릭 멈춤 콘솔 Esc SITL 창
상황: SITL 검은 창을 클릭한 뒤 창 제목이 '선택 C:\...\ArduPlane.exe'로 바뀌고, RealFlight와 Mission Planner가 멈춥니다.
원인: Windows 콘솔 창은 안을 클릭하면 '선택' 모드가 됩니다. 이 동안 SITL은 글자를 출력하려다 멈추고, SITL을 기다리는 RF도 따라 멈춥니다.
해결:
1. SITL 창을 누른 채 Esc를 누르거나 마우스 오른쪽 버튼을 누르면 풀립니다.
2. 수업 중에는 SITL 창 안을 클릭하지 않도록 안내하고, 창은 최소화해 둡니다.

# SITL 창에 'connect failed'가 계속 나옴
검색어: connect failed 18083 RealFlight Link FlightAxis 연결 안 됨
상황: SITL 검은 창에 'Starting controller at 127.0.0.1' 다음 'connect failed'가 반복됩니다.
원인: SITL이 RealFlight(포트 18083)에 연결하지 못하고 있습니다. RF가 꺼져 있거나 RealFlight Link가 꺼져 있습니다.
해결:
1. RealFlight가 켜져 있고 기체가 선택되어 있는지 봅니다.
2. RF Settings → Physics → RealFlight Link = Yes인지 봅니다(도우미 상태 줄의 RealFlight Link). 바꿨다면 RF를 다시 켭니다.
3. RF 9와 Evolution을 동시에 켜지 않습니다(둘 다 18083을 씁니다).

# SITL 창에 'Starting controller at 127.0.0.1'이 계속 반복됨
검색어: Starting controller 반복 리셋 Reset 스위치 버튼 계속 다시 연결
상황: SITL 검은 창에 같은 줄이 몇 초마다 계속 나오고, RF 기체가 계속 리셋됩니다.
원인: RF가 리셋될 때마다 SITL이 연결을 처음부터 다시 합니다. 조종기의 Reset 버튼·스위치가 눌린 채이거나, 기체가 계속 넘어져 자동 리셋이 반복되는 경우입니다.
해결:
1. 조종기 스위치를 모두 기본 위치로 둡니다. 동봉 조종기의 RF Reset 버튼은 연결 중에 누르지 않습니다.
2. ① 진단 보고서에 'Reset 기능에 지정된 조종기 입력'이 나오면, RF 조종기 설정에서 그 지정을 없앱니다.
3. Automatic Reset Delay를 10으로 늘립니다.

# 'Q_ASSIST_SPEED is not set'으로 Arm 거부
검색어: Q_ASSIST_SPEED not set Arm 아밍 거부 PreArm 파라미터 없는 파라미터 Q_ENABLE
상황: 파라미터를 넣었는데 Arm하면 'Q_ASSIST_SPEED is not set'이 나옵니다.
원인: 파라미터를 한 번만 불러왔습니다. 새 SITL은 Q_ENABLE = 0이라 Q_로 시작하는 파라미터가 아직 없어서, 첫 번째에는 Q_ 항목이 '없는 파라미터'로 건너뛰어집니다.
해결:
1. SITL을 다시 켜고 Full Parameter List에서 Refresh Params를 누릅니다.
2. 같은 파일로 Load from file → Write Params를 한 번 더 하고 SITL을 다시 켭니다.
3. Q_ASSIST_SPEED가 14(Fighter는 12)인지 확인합니다.

해결:
1. RealFlight를 한 번 켰다가 끄고, 최근에 바뀐 RealFlight.ini가 들어 있는 문서\RealFlight 9 폴더를 찾습니다. RF가 실제로 쓰는 폴더입니다.
2. 도우미 '1. 대상 확인'에서 그 폴더를 고르고 '2. 모델 준비'부터 다시 합니다.
3. RF Import 창에서는 도우미 '3. RF에서 Import'의 'Import 폴더 열기'로 열린 경로로 이동해 파일을 고릅니다.

# 도우미: '문서 폴더가 OneDrive · 이 PC는 설치 불가'
검색어: OneDrive 원드라이브 문서 폴더 설치 불가 동기화 Linked cloud
상황: 도우미 오른쪽 위에 OneDrive 경고가 나오고, 모델 준비를 누르면 멈춥니다.
원인: 문서 폴더가 OneDrive에 있습니다. RealFlight와 Mission Planner가 문서 폴더에 계속 쓰는 파일을 OneDrive가 동기화하면서 잠그거나 깨뜨릴 수 있어서, 도우미는 이런 PC에는 설치하지 않습니다.
해결:
1. 이 PC에는 설치하지 않는 것이 기본입니다.
2. PC 주인이 동의하면 OneDrive 설정 → 동기화 및 백업 → 백업 관리에서 '문서' 백업을 끌 수 있습니다. 그 뒤에는 RealFlight를 한 번 켰다 끄고, 새 문서 폴더(C:\Users\이름\Documents)의 RealFlight 9 폴더를 도우미에서 고릅니다(위 'RFX\SJARC가 없음' 항목).

# 'Windows의 PC 보호' 창
검색어: Windows의 PC 보호 SmartScreen 실행 안 됨 보안 경고 추가 정보
상황: 도우미를 실행하면 파란 'Windows의 PC 보호' 창이 나옵니다.
원인: 코드 서명이 없는 프로그램이라 나오는 경고입니다.
해결:
1. '추가 정보'를 누르고 '실행'을 누릅니다.

# 도우미: 'RealFlight · Mission Planner · SITL을 먼저 모두 종료하세요'
검색어: 먼저 모두 종료 Close RealFlight 실행 중 파일 작업
상황: 모델 준비나 검사·패치를 누르면 이 메시지가 나오고 멈춥니다.
원인: 파일을 바꾸는 동안 프로그램이 같은 파일을 쓰면 깨질 수 있어서, 켜져 있으면 작업하지 않습니다.
해결:
1. RealFlight, Mission Planner, SITL 창을 모두 닫고 다시 누릅니다. '응답 없음'이면 작업 관리자에서 끝냅니다.

# 도우미 목록에 RealFlight가 없음
검색어: RealFlight 없음 목록 비어 있음 찾지 못함 실행 파일 직접 선택 문서 폴더 없음
상황: '1. 대상 확인'의 목록이 비어 있거나 문서 폴더가 없다고 나옵니다.
원인: RealFlight를 한 번도 실행하지 않아 문서 폴더가 아직 없거나, 다른 위치에 설치되어 있습니다.
해결:
1. RealFlight를 한 번 실행했다가 종료한 뒤 '다시 검색'을 누릅니다.
2. 그래도 없으면 '실행 파일 직접 선택'으로 RealFlight.exe(또는 RealFlight64.exe)를 고릅니다.
