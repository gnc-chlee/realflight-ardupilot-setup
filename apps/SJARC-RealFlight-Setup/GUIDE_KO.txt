ArduPilot SITL 연결 안내 — 자동 ARM / 이륙 없음

이 도우미의 완료 표시는 모델 파일 준비·검사 결과입니다.
RealFlight 안에서의 Import, 조종기 캘리브레이션, SITL 파라미터 적용은 직접 확인합니다.

1. 모델 Import 및 로드

• 여러 RF 버전이 설치되어 있으면 도우미 상단에서 실행 파일과 문서 폴더를 먼저 선택합니다.
  '3. RF에서 Import'의 'RealFlight 열기'로 선택한 제품을 열고, 그 대상의 Import 폴더에서만 RFX를 가져옵니다.
  RF9와 Evolution에 모두 넣으려면 대상을 바꿔 각각 진행합니다.
• RealFlight 8 / 9 / 9.5 / 9.5S:
  Simulation → Import → RealFlight Archive (RFX/G3X)
• Evolution:
  My RealFlight → Import → RealFlight Archives
• 도우미에 IMPORT_REQUIRED로 표시된 파일만 가져옵니다. (제조사 원본 RFX 그대로입니다.)
  기존 기체를 원본 RFX로 다시 Import하여 덮어쓰지 마세요.
• Import 끝에 '경로를 찾을 수 없습니다' 오류 창이 나오면 확인을 누릅니다.
  원본에 제작자 PC 경로가 들어 있어서 생기며 무해합니다.
  RF 8/9는 RealFlight가 Import한 경로를 그대로 씁니다(경로 보정은 Evolution에서만).
• Import 완료 후 RealFlight를 완전히 종료하고 'Import 후 검사·패치'를 누릅니다.
  Import하지 않은 기종은 체크를 해제한 뒤 누릅니다.
• 인터넷이 없으면 원본 RFX·param 8개 파일을 이 EXE와 같은 폴더에 두세요.
  해시가 맞는 파일만 사용합니다.
• 다시 RF를 열어 Aircraft → Select Aircraft (Evolution은 Fly 아래)에서 선택합니다.
  원래 이름으로 고릅니다: STRIVERminiVTOL · Pioneer · fighterVTOL · HERO2180(Hero).
  다른 이름으로 저장한 사본은 패치되지 않고 발사 방식(손 던지기 등)이 다를 수 있습니다.
• 경로 오류가 지속되면 비행하지 말고 작업 보고서를 보관하세요.
• RF 8/9에서 이전 도우미(v0.1.2/v0.1.3)로 경로 보정 후 FLY 시 크래시가 나던 기체는
  RF 종료 후 3번을 다시 누르면 Import 경로로 되돌아갑니다(재Import 불필요).
• Evolution에서 보정 후에도 기체가 로드되지 않으면: '백업에서 복구'로 최근 작업부터 되돌린 뒤,
  '모델·텍스처 경로 보정' 체크를 끄고 3번을 다시 누르면 신호만 보정합니다.

2. RF의 FlightAxis 설정 확인

8/9 계열: Settings → Physics
Evolution: ESC → Settings → Physics → Quality

  RealFlight Link Enabled = Yes
  Pause Sim When in Background = No
  Pause Sim When in Menu = No
  Automatic Reset Delay = 2.0초

도우미가 해당 INI 키를 발견하면 백업 후 적용합니다(RF 8/9: FlightAxisLinkEnabled, Evolution: RealFlightLinkEnabled).
키가 없었다면 화면에서 직접 설정하고 RF를 재시작합니다.
일시정지 해제는 백그라운드에서도 시뮬레이션이 계속된다는 의미입니다.
RF가 정상 실행되려면 지원 조종기/조이스틱이 필요할 수 있습니다. 이 도우미는 드라이버를 설치하지 않습니다.

3. Mission Planner에서 ArduPlane SITL 실행

연결 구조 (위 그림)
  조종기 → USB → RealFlight가 읽음
  RealFlight ↔ ArduPilot SITL: FlightAxis, TCP 18083. 기체 상태와 모터·서보 출력을 주고받습니다.
  ArduPilot SITL ↔ Mission Planner: MAVLink. 화면·파라미터·모드가 오갑니다.
    TCP 5760(MP가 접속) 또는 UDP 14550(SITL이 보내고 MP가 스스로 연결) 중 아무거나 씁니다.

가장 쉬운 방법: 이 화면의 [SITL 시작 (flightaxis)]
• RealFlight를 켜고 기체를 고른 뒤 누릅니다.
• 항상 flightaxis로, 같은 파라미터 저장소(문서\Mission Planner\sitl\flightaxis)로, Wipe 없이 켭니다.
• Mission Planner가 안 켜져 있으면 켜 주고, MP가 UDP 14550으로 스스로 연결합니다.
  오른쪽 위 단추가 DISCONNECT로 바뀌면 연결된 것이니 다시 누르지 않습니다.
• 끌 때는 [SITL 종료]를 누르거나 SITL 검은 창을 닫습니다.

Mission Planner의 Simulation 탭에서 직접 켜는 방법
• 실제 비행 컨트롤러의 USB/텔레메트리를 분리합니다.
• RF에서 원하는 모델을 고른 뒤 Mission Planner를 실행합니다.
• Config/Tuning → Planner → Layout을 Advanced로 설정합니다.
• Simulation → Model = flightaxis → Plane(고정익) 아이콘을 선택합니다.
  Model을 flightaxis로 고르지 않으면 SITL이 RF와 따로 돌아서, RF 기체는 넘어지는데 MP 화면은 그대로입니다(배터리 12.60V 고정).
  이 네 기종은 QuadPlane이므로 Copter 아이콘이 아닙니다.
• Wipe는 사용하지 않습니다. 기존 PID·미션을 지울 수 있습니다.
• 설치할 ArduPlane 버전과 제조사 파라미터 버전을 먼저 맞춥니다.
• RF에서 Space/Reset을 눌러 자세·위치를 리셋하고 FlightAxis 연결 메시지를 확인합니다.
• 켜는 순서: RF 실행 → 기체 선택 → Mission Planner → Simulation. 끄는 순서: Mission Planner(SITL) 먼저, RF 마지막.
• 연결 중 RF가 '응답 없음'이 되면 RF 창을 닫기 전에 왼쪽 아래 '연결 문제 해결'의 ① 진단 보고서를 먼저 만들고,
  SITL 검은 창을 사진으로 남깁니다. 그다음 그 화면의 순서대로 진행합니다.
• MP가 자동 연결하지 않으면 SITL이 실제 실행 중인지 확인한 후
  TCP, 127.0.0.1, 기본 포트 5760으로 연결합니다.
  RF FlightAxis 포트 18083은 MP의 MAVLink 접속 포트가 아닙니다.
• '로컬 연결 포트 확인'은 TCP 수신 대기 목록만 읽습니다. 실제 접속/패킷 전송을 하지 않습니다.
  해당 프로세스·접속 가능 여부·기체·프로토콜 확인을 대신하지 않습니다.

4. 파라미터 — 기존 설정 백업부터

연결 대상이 DISARM된 SITL인지 확인하고, Full Parameter List → Save to file로 전체 파라미터를 먼저 저장합니다.

[이미 해당 기종이 설정된 SITL]
  Q_FRAME_CLASS=1, Q_FRAME_TYPE=1(Quad X)을 확인합니다.
  MFE_MotorMap_ONLY.param을 Load from file → 변경 항목 확인 → Write Params 합니다.
  SERVO9_FUNCTION = 33 (앞오른쪽 / Motor1)
  SERVO10_FUNCTION = 34 (뒤왼쪽 / Motor2)
  SERVO11_FUNCTION = 36 (뒤오른쪽 / Motor4)
  SERVO12_FUNCTION = 35 (앞왼쪽 / Motor3)
  DISARM 상태로 SITL을 재시작하고 위 값을 다시 읽어 확인합니다.
  제조사 param 파일을 다시 불러오면 SERVO11/12가 35/36으로 돌아가므로 MotorMap을 다시 적용합니다.
  FLTMODE_CH(제조사 값 8)는 조종기의 모드 스위치 채널에 맞춥니다.

[새 SITL 환경]
  Parameters 폴더에는 각 기종의 제조사 ArduPlane 4.4.4 원본도 보관합니다.
  반드시 선택한 모델에 맞는 기본 파라미터를 먼저 적용한 후, MotorMap 오버레이를 적용합니다.
  원본은 4.4.4용입니다. 최신 Stable(예: 4.7)에는 이름·단위가 달라진 항목이 있습니다.
  이 도우미는 버전 변환이나 최신 펌웨어 전체 파라미터 호환을 검증하지 않습니다.
  원본을 최신 버전에 무작정 전부 쓰지 마세요. 버전 일치 또는 별도 변환·검증이 필요합니다.
  누락·거부 파라미터가 나오면 중단하고 기록합니다. 완료되지 않은 설정으로 비행하지 않습니다.
  기종별 SITL 저장소를 분리하거나, 기종 교체 시 전체 설정을 다시 확인합니다.

Hero는 V-tail(SERVO2=79, SERVO4=80)입니다. 다른 기종의 엘리베이터/러더 설정을 복사하지 마세요.
제조사 PID를 그대로 두며 사용자가 이전에 조정한 롤 P값을 배포 기본값으로 섞지 않습니다.

5. DISARM 상태 사전 검증

• RF Electronics의 CH9=FR / CH10=RL / CH11=RR / CH12=FL 확인.
• RF 모터 입력 11/12까지 다시 바꾸면 이중 보정이 됩니다. 배선을 임의로 바꾸지 마세요.
• 조종기는 해당 PC에서 직접 캘리브레이션. 타 PC GUID/교정값을 복사하지 않습니다.
• Aileron=오른쪽 좌우 / Elevator=오른쪽 상하 / Throttle=왼쪽 상하 / Rudder=왼쪽 좌우.
• Software Radio Mixes On / Software Radio Dual Rates and Expo Off를 기준으로 확인합니다.
  CH1~7 믹스는 보존되어 있으므로 해당 조종기에 적합한지 별도 확인합니다.
• MP Status ch3in: 스로틀 최하/최상 약 1000/2000.
• MP Status ch2in: 피치 전진/당김 약 1000/2000.
• 3단 모드 스위치가 움직이는 chNin이 FLTMODE_CH와 같은지, QSTABILIZE/QHOVER/FBWA 지정 확인.
• MANUAL에서 조종면 방향 확인. Pioneer 엘리베이터와 Hero V-tail은 개별 검증합니다.

그 뒤 사용자가 직접 수직비행부터 단계적으로 시험합니다. 이 프로그램은 ARM/이륙을 수행하지 않습니다.
RF8+Hero는 사용자 적용 성공 보고가 있지만, 이 설치 도우미의 모든 버전·기종에 대한 비행 검증은 아닙니다.
